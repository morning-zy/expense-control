# 部署说明（expense-control）

面向 Windows + Git Bash，脚本在 Linux 上同样可用。

---

## 1. 前置条件

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 21 | `java -version` 能看到 21 即可 |
| Maven | 3.9+ | 只用打包，不装也行（用 IDEA 的 Maven 面板） |
| MySQL | 8.0 | 库名 `expense_control`，字符集 `utf8mb4` |

---

## 2. 建库建表

```bash
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS expense_control DEFAULT CHARSET utf8mb4;"
mysql -uroot -p expense_control < docs/sql/schema.sql
mysql -uroot -p expense_control < docs/sql/data.sql
```

`data.sql` 里所有员工的初始密码都是 **`123456`**，存的是 PBKDF2 哈希，不是明文。

**建应用账号（生产必须做，别用 root 跑应用）**：

```sql
CREATE USER 'expense_app'@'localhost' IDENTIFIED BY '换成你的密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON expense_control.* TO 'expense_app'@'localhost';
-- 注意：不给 DDL 权限。应用只该读写数据，不能改表结构
FLUSH PRIVILEGES;
```

---

## 3. 配置

复制模板并填写：

```bash
cp src/main/resources/application-dev.yml.example src/main/resources/application-dev.yml
```

`application-dev.yml` 已被 `.gitignore` 排除，**不要把真实密码提交上去**。

JWT 密钥（`app.jwt.secret`）：

- 开发环境用 `application.yml` 里的默认值即可
- **生产环境必须用环境变量覆盖**，且长度 ≥ 32 字节：

```bash
export JWT_SECRET="生产环境用一段足够长的随机字符串"
```

`start.sh` 会自动把它转成 `--app.jwt.secret=...` 传进去。

---

## 4. 打包

```bash
mvn clean package -DskipTests
```

产物：`target/expense-control-0.0.1-SNAPSHOT.jar`（fat jar，内嵌 Tomcat，不需要单独装容器）。

---

## 5. 启停

```bash
./scripts/start.sh          # 默认 8081 端口
./scripts/start.sh 8082     # 换端口
./scripts/status.sh         # 健康检查
./scripts/stop.sh           # 优雅停止（10 秒不退则强杀）
```

`start.sh` 做的事：

1. 检查 java 和 jar 是否存在（缺了直接报错，不会跑到一半才崩）
2. 检查是否已经在跑（避免两个进程抢端口）
3. `nohup java -jar` 后台启动，日志追加到 `logs/app.log`，pid 写 `logs/app.pid`
4. **轮询 `/api/ping` 直到就绪**（最多 30 秒），就绪才返回 0 —— 这样能直接接进 CI

Git Bash 的坑：`java.exe` 不认 `/e/IdeaProjects/...` 这种路径，脚本里用 `cygpath -w` 转成了 `E:\...`。Linux 上没有 `cygpath`，会走 else 分支用原路径。

---

## 6. 验证部署

```bash
# 1. 健康检查（不需要登录）
curl http://localhost:8081/api/ping

# 2. 未登录访问受保护接口 → 401
curl http://localhost:8081/api/expense-forms

# 3. 登录拿令牌
curl -X POST http://localhost:8081/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"empNo":"E001","password":"123456"}'

# 4. 带令牌访问
curl http://localhost:8081/api/expense-forms \
  -H "Authorization: Bearer <上一步拿到的 token>"
```

---

## 7. 上线前必须改的三项

| 项 | 改法 |
|---|---|
| JWT 密钥 | 环境变量 `JWT_SECRET`，≥32 字节随机串 |
| 日志级别 | `application.yml` 里 `log-impl` 关掉（`StdOutImpl` 会把每条 SQL 打到控制台） |
| SQL 日志 | 同上，生产环境开 SQL 日志会拖慢并且泄露数据结构 |

另外两件事建议做但没做（时间够再说）：

- **反向代理**：ngrok / cloudflared 把 8081 暴露成公网 HTTPS 地址，面试时能直接给链接看
- **开机自启**：Linux 用 systemd unit；Windows 用任务计划程序

---

## 8. 常见问题

| 现象 | 原因 |
|---|---|
| `Unable to access jarfile /e/IdeaProjects/...` | Git Bash 路径没转换，确认用的是仓库里的 `start.sh` |
| 启动 30 秒没就绪 | `tail -50 logs/app.log`，多半是数据库连不上或端口被占 |
| `Port 8080 was already in use` | 本机 8080 常被占用，本项目默认走 8081 |
| 登录一直 401 | 确认请求头是 `Authorization: Bearer <token>`，`Bearer` 后面有一个空格 |
